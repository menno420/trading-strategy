💡 **Session idea:** pre-registration is currently enforced by prose
convention ("grids committed before the sweep ran") — make it a machine
check. Each new sweep summary JSON gains a `preregistered_in` field naming
its anchor (doc path + section for a round-level plan like this one, or the
grid-commit SHA for slice-level registration), and a checker verifies with
pure git arithmetic that the anchor was merged to main in a commit that is
an ancestor of — and earlier than — the commit adding the summary. Payoff:
(a) the Round-2/Round-4 discipline ("this doc predates any outcome")
becomes verifiable instead of asserted — today a reader must trust the
badge prose; (b) it catches the failure mode this session's doc explicitly
worries about (R4-F's "K is never counted down"): a summary whose grid
grew after the anchor is flagged mechanically; (c) it is backfillable over
all merged r2/r3 sweeps as a one-off audit. Not covered by the standing
stack (bench_difficulty, param_stability, oos_coverage, cost-drag,
control_arm_delta, KILL-SIG, round manifest, sweep-runner extraction):
those grade results or selectors; this one grades the *ordering of
commitments* — the thing pre-registration actually is.
